00 Scope — one database, one repository

main.py opens with the whole scope in one line: “build an app for one repo, then serve it over stdio.” The database defaults to <root>/.code-atlas/graph.db, resolved from the root handed to load_config(root).

No table carries a project column

nodes.file_path is repo-relative and qualified_name carries no repo prefix. Two repositories mean two server processes over two databases: nothing in one index can be reached from the other, and no answer can mix them. Merging two trees into one graph would collide on UNIQUE(qualified_name, file_path) the moment they share a namespace.

working_roots is not a project mechanism — it narrows what the onboarding surfaces present and leaves the graph whole.

Connection state, set outside any transaction because foreign_keys is silently ignored inside one: journal_mode=WAL · foreign_keys=ON · busy_timeout=5000.

02 What holds them together

A qname lookup may return more than one candidate

Because qualified_name is unique only per file, a lookup returns one or more nodes. That is a multi-candidate HEURISTIC, not a lost row. The same-file case is different — one file may legally declare a qname twice (a function_exists guard's two branches, a fixture carrying both interface X and class X) and would trip the UNIQUE, so replace_file_rows de-dupes keep-first in source order before insert. The file soft-succeeds with one node per qname instead of aborting the build; NULL and anonymous qnames are never collapsed.

No migration runner, and a mismatch has a direction

The database is a derived cache, so a version mismatch fails loud. The stamp is read before the DDL runs, so a database this build cannot read is never written to.

An index older than the server is a stale cache — the build deletes and rebuilds it in-band. An index newer than the server means the server process is the stale one: the index is current, and deleting it would destroy a good graph to write an older one, so the build refuses and leaves the file untouched. The fix is restarting the client, not rebuilding.

07 What the schema cannot express

No project column

by design

One database per repository. Several projects means several MCP processes, each with its own graph.db.

No Table → Table edge

open

The T-SQL adapter drops FOREIGN KEY on purpose — foreign, primary, key and constraint sit in the NOT_A_COLUMN set so they are not read as columns. Table and Column nodes exist, but nothing relates them across tables, so no ER view is derivable. Worth noting for whoever takes it: REFERENCES is already in EDGE_KINDS and FQN_EDGE_KINDS, so a Column → Column link needs no contract bump.

No READS

open

WRITES has no counterpart: SELECT … FROM and JOIN emit no edge. Which routine writes this table is answerable; which routine reads it is not.
