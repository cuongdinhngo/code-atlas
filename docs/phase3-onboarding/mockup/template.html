anchor-repo — system map

01Six things to know before changing a line

What the directory tree will not tell you, and the cause of most surprising bugs.

02Domain → folders

The only bridge between "I was asked to fix screen X" and "which file do I open". Module names come from the application/ and modules/ folders in the code. Click a row to open it in the search box.

03Sitemap — where the code lives

Tile area = symbol count (class, method, function, property). Colour = the responsibility layer holding the majority inside that tile. Click to drill in.

04Responsibility layers & class spread

The layer is inferred from the role of the deepest folder (controller / model / service / view / job…), not the top-level folder name. The bar shows whether a layer is OOP or procedural script.

05Who calls whom

All layers, nothing trimmed. The brighter a cell, the more dependencies. Row = calling layer, column = called layer.

06Hubs — change these and you touch the whole system

Ranked by how many files depend on them. This is the list that needs the closest review.

07ALPHA / BETA duplication — the biggest trap

Paste a legacy/alpha/… or legacy/beta/… path into the search box (Ctrl K) — and it returns the parallel copy immediately, if one exists.
