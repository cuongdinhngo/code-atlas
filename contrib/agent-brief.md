## code-atlas — when to ask the graph

Generated by `scripts/gen_skill.py` from the `which_tool` recognition map.
Do not edit by hand — regenerate with
`python scripts/gen_skill.py --write-agent-brief <repo>`.

### Before renaming a symbol

- Where is this symbol used -> find_references.
- Who calls this function/method -> find_callers.
- What breaks if I change this -> impact.

### After editing indexed code

- Is the index built/fresh/healthy, what next? -> get_index_status (call first).
- Who calls this function/method -> find_callers.
- What breaks if I change this -> impact.

### First session on this repo

- Is the index built/fresh/healthy, what next? -> get_index_status (call first).
- What are this codebase's layers, and how do they depend on each other -> architecture_overview.
- What should I read first, in dependency order -> guided_tour.

### A name that exists in two languages

- Find a symbol by partial name/text -> search_symbol.
- Is the index built/fresh/healthy, what next? -> get_index_status (call first).

### Writing the PR claim

- Who calls this function/method -> find_callers.
- What breaks if I change this -> impact.
- Is the index built/fresh/healthy, what next? -> get_index_status (call first).

### Explaining how a request moves through the system

- Is the index built/fresh/healthy, what next? -> get_index_status (call first).
- How does this codebase route an incoming request to the code that produces the response -> trace_capability.
- What are this codebase's layers, and how do they depend on each other -> architecture_overview.

### A bug report or test doc names a URL

- Find a symbol by partial name/text -> search_symbol.
- How does this codebase route an incoming request to the code that produces the response -> trace_capability.
- What breaks if I change this -> impact.

### How to spend the calls

- **Ask the index first, then follow through.** Structural questions take more than one call: `search_symbol` → `read_symbol`, `find_callers` → `impact`. One lookup followed by a grep sweep is the failure mode this brief exists to stop.
- **Call `get_index_status` when you are unsure the index is current** — and read `staleness`. On a `behind` index `find_callers` / `find_references` answer labelled `index_behind` with `last_commit`, and `search_symbol` flags drifted rows `source_stale`; `behind_because` lists the changed paths. A subject whose changed file cannot be re-read still refuses `index_stale` (`read_symbol` too); a caller's hint names the `serve_behind: true` call to copy.
- **Prefer one call over a sweep of ten.** `search_symbol` takes a list of `queries`.
- **Working in a git worktree of the indexed repo?** Pass `caller_root` = your `git rev-parse --show-toplevel` to `read_symbol`, `file_outline`, `search_symbol`, `find_callers` and `find_references`: they then answer from your worktree's files (`overlay: worktree`), not the main checkout's. Other tools answer about the built index.

### Read what the answer says about itself

- `total_count` is the population, `truncated` describes the page alone — page 1 of `find_callers` is tier-ordered (RESOLVED first), not a ranking of importance.
- `production_count` / `test_count` split inbound answers by the caller's role. *Three callers* and *three callers, all in one test* are different answers; `exclude_tests=true` filters before paging on `find_callers` (any depth — test nodes are pruned from the walk) and on `search_symbol` / `impact`, so page 1 is production.
- `confidence_tier` is per edge: `RESOLVED` is a linked definition, `HEURISTIC` and `DYNAMIC` are candidates. Never quote a candidate as a fact.
- **`unconfigured_adapters`, `unindexed_languages` and `unindexed_same_basename` mean the index never looked** — not that nothing is there. They are omitted when empty, so seeing one is the signal, and `detail_level: "minimal"` hides all three.

### What it cannot answer — use grep instead

The index holds what the adapters parsed, so a question whose answer is an **absence** cannot be settled here: *is there a call site that forgets the check*, *does anything still use the old constant*, *which of these has no test*. Ask the positive form (`find_callers`, `find_references`), then subtract — and keep grep for literal text in strings, comments and config.

### Two traps that cost real time

- **A name defined in more than one tree** (`src/` beside a `legacy/` copy) makes `impact` and `read_symbol` answer `reason: subject_ambiguous` with no rows — and the payload carries `ambiguous_definitions`. Re-ask `read_symbol` with `path_prefix` naming one site from that list (327); do not read the empty result as no impact.
- **Mirrored trees inflate a result set.** A hit carries `mirror_counterpart` when an indexed twin exists; read it before concluding a symbol has many call sites.

### Filters, writers, and what the index will not name (313)

- **Narrow a large `search_symbol` page with `kind:` or `namespace`.** A common token across File/Class/Method rows is not a reason to eyeball hundreds of hits — pass `kind` (a contract node kind) or `namespace` and re-ask.
- **Scope a `search_symbol` / `find_references` / `read_symbol` page to a subtree with `path_prefix`.** An index-root-relative plain prefix (`src/`); a hit outside it answers `path_excluded` (search/refs) or `no_such_symbol` naming the filter (read) — not a silent wrong body (315/327).
- **`find_references` on a Table or Column returns its writers** — linked `WRITES`, plus `DELETES` on the Table (278/328). Prefer that over asking who calls a nearby method when the question is *what writes this column*. Pass `kinds: ["READS"]` for who reads the table instead — routines that `SELECT` from it and strings that begin `SELECT … FROM` it (390).
- **A dynamic-SQL / `EXEC`-created object is not a symbol.** Grep the SQL text; the index reads as absence. `find_orphans` then says `status=resolution_unmodelled` when a language stamped `dynamic_sql` (296).
- **A runtime-loaded module is not an edge either.** A computed `import()` / `require()` / `importlib` load stamps `dynamic_import` (one built from `__dirname`/`__file__` and literals, or a literal `import_module`, is linked — 370/373), a registered class autoloader stamps `autoload`: the target is never linked, so a missing importer is not proof of none — Grep the loader call. `find_orphans` answers `status=resolution_unmodelled` for either (279/294/295).
- **`find_orphans` has no path scope** — it walks the whole index from `CA_ENTRY_POINTS`. Do not expect a directory filter.
- **A URL or route someone reports** is a subject once a `routes` block is declared in a `CA_INDIRECTION_RULES` file: `trace_capability(route=…)` traces from its handler, `impact(routes=[…])` lists the routes a change reaches, `search_symbol` finds a route by key. An unmatched URL answers `no_such_symbol` with `nearest_routes` (385).

### From a shell — no agent turn per answer

- **Many answers, no agent turn each:** `code-atlas query <tool> --args '<json>'` prints the payload the MCP tool returns; `--batch <file.jsonl>` answers one `{"tool": …, "args": {…}}` per line over one opened index. Use it for a script, a CI check or a lint; `code-atlas query --help` lists the exit codes.
- **A pasted signed claim (`code-atlas/2 … call=…`) is a check, not prose:** `--verify-claim '<line>'` / `--verify-claims <file>` re-run it at the current index and answer `holds`, `changed` or `unverifiable`.
- **"Has this method changed since revision X?"** `--snapshot-symbols <out>` at X, then `--changed-since <snapshot> --qname Q --path P` answers per symbol (`unchanged`, `body_changed`, `signature_changed`, `moved`, `removed`, …) — finer than a file diff.

Hooks (edit poke, read/write signal, session state, grep nudge) are opt-in: the Claude Code
plugin or the snippet under `contrib/claude-code/` — the server never writes editor settings.
